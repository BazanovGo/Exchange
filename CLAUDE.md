# Правила работы в этом репозитории

## Публикация результатов в GitHub — обязательно после каждой задачи

Всю работу вести в https://github.com/BazanovGo/Exchange. Задача считается завершённой только
после того, как изменения сохранены, опубликованы и проверены на GitHub.

После выполнения каждой задачи:

1. Сохранить все созданные и изменённые файлы: исходный код, скрипты, конфигурации, тесты,
   документацию, результаты вычислений, графики и отчёты.
2. Проверить работоспособность проекта и зафиксировать результаты тестирования
   (`exchange/tools/run_checks.py`, раздел дописывается в `exchange/docs/VERIFICATION_LOG.md`).
3. Проверить `git status`, включая новые и изменённые файлы, чтобы ничего не потерять.
4. Проверить, что в публикацию не попадут пароли, API-ключи, токены, персональные данные и
   другие конфиденциальные материалы (`run_checks.py` ищет их сам; находку разобрать до коммита).
5. Создать коммит с содержательным описанием изменений.
6. Выполнить `git push` в удалённый репозиторий.
7. Проверить, что коммит действительно опубликован (`git rev-parse HEAD` против
   `git ls-remote origin <ветка>` и запрос коммита через GitHub API).
8. В итоговом отчёте указать ссылку на коммит, перечень изменений и результаты проверок.

Правила:

- Не ограничиваться кодом в чате — создавать реальные файлы в репозитории.
- Не удалять существующие результаты без необходимости.
- Не перезаписывать чужие изменения и не использовать принудительный push.
- Крупные файлы размещать через Git LFS, когда это необходимо и разрешено. Предел GitHub — 100 МБ
  на файл; файлы больше 50 МБ — только с обоснованием. Сырые сетки исследований (гигабайты)
  в git не кладутся: они воспроизводятся скриптами, а в git идут их выгрузки.
- Если публикация невозможна, прямо сообщить причину и что нужно сделать для её устранения.

## Как здесь проверять

```bash
cd exchange
PY_PKG=<python с пакетом exchange и pytest> \
PY_RESEARCH=<python окружения исследования: numba, vectorbt, pandas<3> \
python tools/run_checks.py --title "<что сделано>"
```

Скрипт прогоняет тесты пакета (`tests/`) и исследования скользящих средних, статический контроль
(ruff: синтаксис и неопределённые имена), ищет секреты и адреса почты в отслеживаемых и новых
файлах (включая строки xlsx и содержимое `.csv.gz`), проверяет размер файлов и дописывает раздел
в журнал проверок. Ненулевой код возврата — публиковать нельзя.

## Где что лежит

- `exchange/` — фреймворк Exchange Research OS и все исследования; описание — `exchange/README.md`.
- `exchange/notebooks/00_presentation.ipynb` — презентация всего проекта.
- `exchange/docs/` — аудит, методология, отчёты по исследованиям, журнал проверок.
- `exchange/research/` — код и машиночитаемые результаты исследований, журнал сделок.
- Корень репозитория вне `exchange/` — исходный проект, разобранный в
  `exchange/docs/ARCHITECTURE_AUDIT.md`.
